# آمدن از discord.py

bisim.py همان API نسخهٔ ۲ discord.py را دارد، پس بیشتر ربات‌ها با دو تغییر منتقل می‌شوند: importها و توکن.
این صفحه هر تفاوت دیگری را فهرست می‌کند تا پس از انتقال چیزی غافلگیرتان نکند.

## importها

```diff
-import discord
-from discord import app_commands, ui
-from discord.ext import commands, tasks
+import bisim
+from bisim import app_commands, ui
+from bisim.ext import commands, tasks
```

سپس در کد `discord.` را با `bisim.` جایگزین کنید: `discord.Embed` می‌شود `bisim.Embed`، `discord.Interaction`
می‌شود `bisim.Interaction` و همین‌طور بقیه. بعضی ربات‌ها ماژول را با نام قدیمش import می‌کنند تا بقیهٔ کد
دست‌نخورده بماند؛ این هم کار می‌کند:

```python
import bisim as discord
```

## توکن

توکن دیسکورد روی بی‌سیم کار نمی‌کند. ربات را در بی‌سیم از بخش تنظیمات، برنامه‌ها بسازید
([ساخت برنامه](creating-an-application.md) را ببینید) و توکنش را مثل قبل به `client.run()` یا `bot.start()`
بدهید. توکن را در یک متغیر محیطی نگه دارید، هرگز در کد.

## نام‌هایی که «Discord» دارند

فقط واژهٔ «Discord» عوض می‌شود؛ بقیهٔ نام‌ها همان نام‌های discord.py هستند.

| discord.py | bisim.py |
| --- | --- |
| `discord.DiscordException` | `bisim.BisimException` |
| `discord.DiscordServerError` | `bisim.BisimServerError` |
| `discord.utils` | `bisim.utils` |
| `discord.utils.DISCORD_EPOCH` | `bisim.utils.BISIM_EPOCH` |
| `discord.gateway.DiscordWebSocket` | `bisim.gateway.BisimWebSocket` |

`except discord.DiscordException` می‌شود `except bisim.BisimException` و همچنان همهٔ خطاهای کتاب‌خانه را
می‌گیرد.

## اینتنت‌ها

اینتنت‌ها هر جا که discord.py می‌پذیرد پذیرفته می‌شوند و هیچ چیزی را تغییر نمی‌دهند. ربات بی‌سیم هر رویدادی را
که دسترسی‌هایش اجازه بدهند دریافت می‌کند و پیام‌ها همیشه متنشان را دارند، پس
`intents.message_content = True` و `intents.members = True` بی‌ضررند و لازم نیستند. هم
`bisim.Intents.default()` و هم `bisim.Intents.all()` کار می‌کنند. خطای `PrivilegedIntentsRequired` هرگز رخ
نمی‌دهد.

## شروع به کار

گیت‌وی بی‌سیم IDENTIFY و رویداد READY ندارد. bisim.py پس از اتصال، سرورها، کانال‌ها، نقش‌ها و اعضای ربات را از
راه REST API بارگذاری می‌کند و در هر سرور مشترک می‌شود، سپس `on_ready` را صدا می‌زند. همان‌طور که انتظار
دارید، وقتی `on_ready` اجرا می‌شود حافظهٔ موقت پر است.

- `on_ready` یک بار صدا زده می‌شود. پس از اتصال دوباره، کتاب‌خانه همه‌چیز را دوباره بارگذاری می‌کند و
  `on_resumed` را صدا می‌زند؛ تغییرهایی که در این میان پیدا کند به‌صورت رویدادهای معمول می‌رسند.
- `on_guild_available` برای هر سرور هنگام بارگذاری‌اش صدا زده می‌شود و `on_guild_join` وقتی ربات بعداً به
  سروری اضافه شود.
- `setup_hook` مثل discord.py پس از ورود و پیش از اتصال اجرا می‌شود. جای همگام‌سازی دستورها و ثبت نماهای
  ماندگار همین‌جاست.

## چیزهایی که بی‌سیم ندارد

بی‌سیم رشته‌ها (threads)، کانال‌های استیج، فروم و رسانه، رویدادهای زمان‌بندی‌شده، شاردینگ، تصویر از ربات،
تماس خصوصی برای ربات، بسته‌های استیکر، قالب سرور، ویجت، SKU و قابلیت‌های پولی ندارد. فراخوانی هر چیزی که به این‌ها نیاز
دارد خطای `bisim.NotSupported` می‌دهد که زیرکلاس `bisim.ClientException` است و پیامش نام آن قابلیت را می‌گوید:

```python
try:
    await channel.create_thread(name='Ideas')
except bisim.NotSupported as error:
    print(error)  # Threads is not supported on Bisim.
```

هیچ چیزی بی‌صدا شکست نمی‌خورد. چند نمونه از فراخوانی‌هایی که این خطا را می‌دهند:

| بخش | خطای `NotSupported` می‌دهد |
| --- | --- |
| صدا | تعیین bitrate، سقف کاربران یا منطقه هنگام ساخت یا ویرایش کانال صوتی؛ گفت‌وگوی متنی در کانال صوتی |
| کانال‌ها | رشته‌ها، کانال‌های استیج، فروم و اطلاع‌رسانی، دنبال کردن کانال، تغییر نوع کانال |
| پیام‌ها | بازارسال و انتشار پیام، تغییر پیوست‌های یک پیام |
| تعامل‌ها | فایل، پیوست و نظرسنجی در پاسخ‌ها و پیام‌های پیگیری تعامل |
| اجزا | `default_values` در منوهای انتخاب، دکمه‌های پولی (`sku_id`)، `Client.add_dynamic_items()` |
| دستورهای برنامه | تغییر دسترسی جداگانه برای هر دستور (`AppCommand.fetch_permissions()`) |
| سرورها | ساخت، حذف یا قالب‌گیری سرور به‌دست ربات، خواندن دعوت اختصاصی، آیکون نقش و رنگ گرادیانی، ویرایش ایموجی یا استیکر |
| حساب ربات | تغییر تصویر، بنر یا معرفی ربات از راه کتاب‌خانه |
| وب‌هوک‌ها | تصویر، فایل، اجزا، رشته و نظرسنجی در پیام‌های وب‌هوک |
| ext.commands | `Context.from_interaction()`؛ دستورهای ترکیبی (hybrid) و `FlagConverter` هنوز وجود ندارند |

کلاس‌هایی مثل `bisim.Thread`، `bisim.StageChannel` و `bisim.ForumChannel` وجود دارند تا بررسی‌های
`isinstance` همچنان اجرا شوند، اما هیچ شیئی از این نوع‌ها ساخته نمی‌شود. `shard_id` و `shard_count` با یک
هشدار نادیده گرفته می‌شوند و [مرجع API](../reference.md) رویدادهایی را که هرگز رخ نمی‌دهند فهرست می‌کند.

## چیزهایی که کمی متفاوت کار می‌کنند

- **تصویرهای امبد.** تصویر بزرگ، تصویر کوچک و آیکون نویسنده و پانویس باید پیوند `http` یا `https` باشند.
  تصویر `attachment://` از پیام کنار گذاشته می‌شود و یک بار هشدار داده می‌شود. [امبدها](topics/embeds.md) را
  ببینید.
- **طول پیام.** تا ۴۰۰۰ نویسه، در حالی که دیسکورد ۲۰۰۰ نویسه اجازه می‌دهد.
- **فایل‌ها.** `bisim.File` با `send()` کار می‌کند و از راه نشانی‌های بارگذاری بی‌سیم فرستاده می‌شود. به‌طور
  پیش‌فرض تا ۱۰ فایل و هر کدام تا ۱۰ مگابایت.
- **پیگیری تعامل به‌تعویق‌افتاده.** پس از `interaction.response.defer()`، فراخوانی `followup.send()` یک پیام
  تازه می‌فرستد و جای پیام «در حال فکر کردن» را نمی‌گیرد. آن پیام را با `interaction.edit_original_response()`
  پر کنید. [پاسخ به دستورها](slash-commands/responding.md) را ببینید.
- **نام دستورها.** نام دستورهای اسلش حروف کوچک `a-z`، رقم‌های `0-9`، `-` و `_` است و حداکثر ۳۲ نویسه. برای
  نمایش فارسی آن‌ها از [ترجمه‌ها](slash-commands/translations.md) استفاده کنید.
- **شناسه‌ها.** شناسه‌ها مثل discord.py از نوع `int` هستند، اما snowflakeهای بی‌سیم از مبدأ زمانی خودشان شروع
  می‌شوند: `bisim.utils.snowflake_time()` از `BISIM_EPOCH` استفاده می‌کند.
- **محدودیت‌های نرخ.** محدودیت‌های بی‌سیم خودکار رعایت می‌شوند، همان‌طور که discord.py محدودیت‌های دیسکورد را
  رعایت می‌کند.

## فهرست کارها

1. importها را عوض کنید و `discord.` را به `bisim.` تغییر دهید (یا `import bisim as discord`).
2. اگر `DiscordException` و `DiscordServerError` را می‌گیرید، نامشان را عوض کنید.
3. از یک توکن بی‌سیم استفاده کنید.
4. کد را برای رشته‌ها، کانال‌های استیج و فروم، رویدادهای زمان‌بندی‌شده و شاردینگ بگردید و تصمیم بگیرید ربات
   بدون آن‌ها چه کند. ربات صوتی به `pip install "bisim.py[voice]"` نیاز دارد (صفحهٔ [صدا](topics/voice.md)).
5. ربات را اجرا کنید و دستورهایش را یک بار با `tree.sync()` همگام کنید.

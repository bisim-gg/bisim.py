# آمدن از discord.py

bisim.py همان API نسخهٔ ۲ discord.py را دارد، پس بیشتر ربات‌ها با دو تغییر منتقل می‌شوند: importها و توکن.
این صفحه هر تفاوت دیگری را فهرست می‌کند تا پس از انتقال چیزی غافلگیرتان نکند.

## importها

```diff
-import discord
-from discord import app_commands, ui
-from discord.ext import commands, tasks
+import bisim
+from bisim import app_commands, ui
+from bisim.ext import commands, tasks
```

سپس در کد `discord.` را با `bisim.` جایگزین کنید: `discord.Embed` می‌شود `bisim.Embed`، `discord.Interaction`
می‌شود `bisim.Interaction` و همین‌طور بقیه. بعضی ربات‌ها ماژول را با نام قدیمش import می‌کنند تا بقیهٔ کد
دست‌نخورده بماند؛ این هم کار می‌کند:

```python
import bisim as discord
```

## توکن

توکن دیسکورد روی بی‌سیم کار نمی‌کند. ربات را در پورتال توسعه‌دهندگان بی‌سیم بسازید: تنظیمات، پورتال
توسعه‌دهندگان، یا [bisim.gg/developers](https://bisim.gg/developers) ([ساخت برنامه](creating-an-application.md)
را ببینید). توکنش را مثل قبل به `client.run()` یا `bot.start()` بدهید. توکن را در یک متغیر محیطی نگه دارید،
هرگز در کد.

## نام‌هایی که «Discord» دارند

فقط واژهٔ «Discord» عوض می‌شود؛ بقیهٔ نام‌ها همان نام‌های discord.py هستند.

| discord.py | bisim.py |
| --- | --- |
| `discord.DiscordException` | `bisim.BisimException` |
| `discord.DiscordServerError` | `bisim.BisimServerError` |
| `discord.utils` | `bisim.utils` |
| `discord.utils.DISCORD_EPOCH` | `bisim.utils.BISIM_EPOCH` |
| `discord.gateway.DiscordWebSocket` | `bisim.gateway.BisimWebSocket` |

`except discord.DiscordException` می‌شود `except bisim.BisimException` و همچنان همهٔ خطاهای کتاب‌خانه را
می‌گیرد.

## اینتنت‌ها

اینتنت‌ها مثل دیسکورد و با همان بیت‌ها کار می‌کنند: گیت‌وی فقط رویدادهایی را می‌فرستد که زیر پوشش آن‌هاست، و سه
اینتنت ویژه (`members`، `presences` و `message_content`) باید برای ربات در
[bisim.gg/developers](https://bisim.gg/developers) روشن شوند (برنامهٔ شما، **Bot**، **Privileged Gateway
Intents**)، همان‌جا که در Developer Portal دیسکورد بودند. از ۱۰۰ سرور به بعد، بی‌سیم هم باید آن‌ها را تأیید کند.
اینتنت ویژه‌ای که روشن نشده خطای `PrivilegedIntentsRequired` می‌دهد (کد بستن 4014) و اینتنت نامعتبر خطای
`ConnectionClosed` با کد 4013، درست مثل discord.py. پس اینتنت‌هایی را که ربات discord.py شما داشت نگه دارید و
همان اینتنت‌های ویژه را برای برنامهٔ بی‌سیمش روشن کنید. بخش [اینتنت‌ها](topics/events.md#اینتنتها) جزئیات را
دارد.

## شروع به کار

گیت‌وی بی‌سیم IDENTIFY و رویداد READY ندارد. bisim.py پس از اتصال، سرورها، کانال‌ها، نقش‌ها و (با اینتنت
`members`) اعضای ربات را از راه REST API بارگذاری می‌کند و در هر سرور مشترک می‌شود، سپس `on_ready` را صدا می‌زند. همان‌طور که انتظار
دارید، وقتی `on_ready` اجرا می‌شود حافظهٔ موقت پر است.

- `on_ready` یک بار صدا زده می‌شود. پس از اتصال دوباره، کتاب‌خانه همه‌چیز را دوباره بارگذاری می‌کند و
  `on_resumed` را صدا می‌زند؛ تغییرهایی که در این میان پیدا کند به‌صورت رویدادهای معمول می‌رسند.
- `on_guild_available` برای هر سرور هنگام بارگذاری‌اش صدا زده می‌شود و `on_guild_join` وقتی ربات بعداً به
  سروری اضافه شود.
- `setup_hook` مثل discord.py پس از ورود و پیش از اتصال اجرا می‌شود. جای همگام‌سازی دستورها و ثبت نماهای
  ماندگار همین‌جاست.

## چیزهایی که بی‌سیم ندارد

بی‌سیم رشته‌ها (threads)، کانال‌های استیج، فروم و رسانه، رویدادهای زمان‌بندی‌شده، شاردینگ، تصویر از ربات،
تماس خصوصی برای ربات، بسته‌های استیکر، قالب سرور، ویجت، SKU و قابلیت‌های پولی ندارد. فراخوانی هر چیزی که به این‌ها نیاز
دارد خطای `bisim.NotSupported` می‌دهد که زیرکلاس `bisim.ClientException` است و پیامش نام آن قابلیت را می‌گوید:

```python
try:
    await channel.create_thread(name='Ideas')
except bisim.NotSupported as error:
    print(error)  # Threads is not supported on Bisim.
```

هیچ چیزی بی‌صدا شکست نمی‌خورد. چند نمونه از فراخوانی‌هایی که این خطا را می‌دهند:

| بخش | خطای `NotSupported` می‌دهد |
| --- | --- |
| صدا | تعیین bitrate، سقف کاربران یا منطقه هنگام ساخت یا ویرایش کانال صوتی؛ گفت‌وگوی متنی در کانال صوتی |
| کانال‌ها | رشته‌ها، کانال‌های استیج، فروم و اطلاع‌رسانی، دنبال کردن کانال، تغییر نوع کانال |
| پیام‌ها | بازارسال و انتشار پیام |
| تعامل‌ها | نظرسنجی در ویرایش پاسخ (آن را به‌صورت پاسخ تازه یا پیام پیگیری بفرستید) |
| اجزا | دکمه‌های پولی (`sku_id`)، `Client.add_dynamic_items()` |
| دستورهای برنامه | تغییر دسترسی جداگانه برای هر دستور (`AppCommand.fetch_permissions()`) |
| سرورها | ساخت، حذف یا قالب‌گیری سرور به‌دست ربات، خواندن دعوت اختصاصی، آیکون نقش و رنگ گرادیانی، ایموجی محدود به نقش (`Emoji.edit(roles=)`)، توضیح یا ایموجی استیکر (`GuildSticker.edit(description=, emoji=)`) |
| AutoMod | قانون‌های پیوند زیان‌بار و کنش مسدود کردن تعامل‌های عضو |
| حساب ربات | تغییر معرفی ربات (نام کاربری همان نام برنامه است) |
| وب‌هوک‌ها | اجزا، رشته و نظرسنجی در پیام‌های وب‌هوک، پیام موقت از وب‌هوک ساده |
| ext.commands | `Context.from_interaction()`؛ دستورهای ترکیبی (hybrid) و `FlagConverter` هنوز وجود ندارند |

کلاس‌هایی مثل `bisim.Thread`، `bisim.StageChannel` و `bisim.ForumChannel` وجود دارند تا بررسی‌های
`isinstance` همچنان اجرا شوند، اما هیچ شیئی از این نوع‌ها ساخته نمی‌شود. `shard_id` و `shard_count` با یک
هشدار نادیده گرفته می‌شوند و [مرجع API](../reference.md) رویدادهایی را که هرگز رخ نمی‌دهند فهرست می‌کند.

## چیزهایی که کمی متفاوت کار می‌کنند

- **تصویرهای امبد.** تصویر بزرگ، تصویر کوچک و آیکون نویسنده و پانویس پیوند `http` یا `https` هستند، یا مثل
  دیسکورد `attachment://name` برای فایلی که همراه همان پیام فرستاده (یا نگه داشته) می‌شود. تصویر
  `attachment://` که به هیچ فایلی از پیام اشاره نکند کنار گذاشته می‌شود و یک بار هشدار داده می‌شود. بی‌سیم
  فایلی را که امبد نشانش می‌دهد در `message.attachments` نگه می‌دارد (دیسکورد کنارش می‌گذارد)؛ برنامه‌های
  بی‌سیم آن را پنهان می‌کنند. [امبدها](topics/embeds.md) را ببینید.
- **طول پیام.** تا ۴۰۰۰ نویسه، در حالی که دیسکورد ۲۰۰۰ نویسه اجازه می‌دهد.
- **فایل‌ها.** `bisim.File` هر جا که discord.py می‌پذیرد کار می‌کند: `send()`، پاسخ و پیام پیگیری تعامل،
  وب‌هوک‌ها و `attachments=` در ویرایش‌ها (هر `Attachment` نگه داشته می‌شود، هر `File` اضافه می‌شود و فایلی
  که در فهرست نباشد حذف می‌شود). کتاب‌خانه هر فایل را اول در نشانی بارگذاری بی‌سیم می‌گذارد و بعد پیام را
  می‌فرستد. به‌طور پیش‌فرض تا ۱۰ فایل و هر کدام تا ۱۰ مگابایت.
- **پیگیری تعامل به‌تعویق‌افتاده.** پس از `interaction.response.defer()`، نخستین `followup.send()` مثل دیسکورد
  جای پیام «در حال فکر کردن» را پر می‌کند و فراخوانی‌های بعدی پیام تازه می‌فرستند. نظرسنجی نمی‌تواند آن پیام را
  پر کند: اول به پیام «در حال فکر کردن» پاسخ دهید و بعد نظرسنجی را به‌صورت پیام پیگیری بفرستید.
  [پاسخ به دستورها](slash-commands/responding.md) را ببینید.
- **منشن‌ها.** `allowed_mentions` (و `Client(allowed_mentions=)`) مثل دیسکورد کار می‌کنند. منشنی که اجازه
  ندارد به‌صورت متن ساده، یعنی نام آن شخص یا نقش، در پیام نوشته می‌شود و کسی را خبر نمی‌کند؛ پاسخ دادن به
  پیام در بی‌سیم کسی را خبر نمی‌کند، پس `mention_author` فقط همراه پیام فرستاده می‌شود.
- **صداهای ساندبورد.** بی‌سیم هنگام اتصال ربات صداهای سرور را نمی‌فرستد، پس `Guild.soundboard_sounds`
  صداهایی را دارد که کتاب‌خانه دیده است: یک بار `Guild.fetch_soundboard_sounds()` را صدا بزنید تا همه بارگذاری
  شوند.
- **نام دستورها.** نام دستورهای اسلش حروف کوچک `a-z`، رقم‌های `0-9`، `-` و `_` است و حداکثر ۳۲ نویسه. برای
  نمایش فارسی آن‌ها از [ترجمه‌ها](slash-commands/translations.md) استفاده کنید.
- **شناسه‌ها.** شناسه‌ها مثل discord.py از نوع `int` هستند، اما snowflakeهای بی‌سیم از مبدأ زمانی خودشان شروع
  می‌شوند: `bisim.utils.snowflake_time()` از `BISIM_EPOCH` استفاده می‌کند.
- **محدودیت‌های نرخ.** محدودیت‌های بی‌سیم خودکار رعایت می‌شوند، همان‌طور که discord.py محدودیت‌های دیسکورد را
  رعایت می‌کند: همان سرآیندهای `X-RateLimit` و همان سطل‌ها، یک صف برای هر سطل، و صبر تا زمان بازنشانی وقتی
  سطلی تمام شود.

## فهرست کارها

1. importها را عوض کنید و `discord.` را به `bisim.` تغییر دهید (یا `import bisim as discord`).
2. اگر `DiscordException` و `DiscordServerError` را می‌گیرید، نامشان را عوض کنید.
3. از یک توکن بی‌سیم استفاده کنید.
4. کد را برای رشته‌ها، کانال‌های استیج و فروم، رویدادهای زمان‌بندی‌شده و شاردینگ بگردید و تصمیم بگیرید ربات
   بدون آن‌ها چه کند. ربات صوتی به `pip install "bisim.py[voice]"` نیاز دارد (صفحهٔ [صدا](topics/voice.md)).
5. ربات را اجرا کنید و دستورهایش را یک بار با `tree.sync()` همگام کنید.
